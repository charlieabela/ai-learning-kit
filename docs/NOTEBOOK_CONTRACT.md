# The notebook contract

Every notebook in `notebooks/` runs unchanged in **Notebook Tutor** (on the student's own
computer) and in **Colab** (from its Open-in-Colab link), and on a best-effort basis in plain
Jupyter. That works because nothing in a notebook depends on where it runs: the kit finds the
work folder, provides the helpers, and downloads the data. A notebook that follows the rules
below needs no setup instructions beyond "run the first two cells".

`python -m ai_learning_kit.dev.validate` checks every rule marked **(checked)** for every
notebook a session names, and CI executes every notebook on Linux, macOS and Windows.

## 1. Where a notebook lives and how it is found

- `notebooks/<UNIT>/<SESSION>/<SESSION>_<n>_<role>_<name>.ipynb`, for example
  `notebooks/ICS5111/S02/S02_2_explore_walkthrough.ipynb`. No spaces in file names (they end up in
  Colab links).
- The session module lists it in `NOTEBOOKS`, by role: `prepare`, `explore`, `practice`, or `session`
  for a single notebook that covers a whole session. **(checked)**
- Solved (lecturer) versions are never committed: the repository is public. Keep them with the
  lecturer resources. A practice notebook is written so that it runs from top to bottom with its
  blanks unfilled (each exercise returns `None` or prints a prompt until it is completed), so that CI
  can execute the student version itself.

## 2. The opening: two cells, always the same

```python
%pip install -q "ai-learning-kit[graphs]@https://github.com/charlieabela/ai-learning-kit/archive/refs/tags/v0.5.0.zip"
```

```python
import ai_learning_kit as kit
kit.start("ICS5111", "S02")       # downloads the session's datasets the first time
T = kit.tools()                   # the session's helper functions

import numpy as np, pandas as pd, matplotlib.pyplot as plt
from IPython.display import display
SEED = T.SEED
```

- The first code cell is exactly the install line for the current release, with the session's pip
  extra (`EXTRAS` in the session module; none for ARI1101, `graphs` for networkx and scikit-learn,
  `advanced` for PyTorch). It uses GitHub's archive of the release, which needs only pip, and is
  written without spaces around `@`, which lets Notebook Tutor recognise it and skip it. **(checked)**
- The release step writes this line and the metadata below; never edit the version by hand.
- The second code cell starts the session and, when the session has helpers, gets them as `T`.
  Imports the rest of the notebook relies on go in the same cell. (Older notebooks may start the
  session in the third cell after an imports cell; `kit.start` must still come before any other
  use of the kit.) **(checked)**
- A session with graded tasks starts with `kit.start(unit, session, student="Your Name")`; a session
  whose notebooks check themselves needs no name.
- The markdown cell before the opening says, in two or three sentences, what the cells do and that
  nothing has to be downloaded or uploaded by hand. It does not explain Drive folders, ZIPs or paths.

## 3. Nothing that depends on the environment

No cell (after the install line) may **(checked)**:

- import `google.colab`, mount Drive, or call `files.upload()`;
- open, extract or mention ZIP files;
- change `sys.path`, or import helper files that sit next to the notebook;
- install packages (`%pip`, `!pip`, `subprocess ... pip`): a library the session needs is added
  to the kit's pip extras instead;
- hard-code paths such as `/content/drive/...` or `MyDrive`.

Files a notebook writes use plain relative names (`outputs/comparison.csv`): `kit.start` has made
the notebook's folder (or, in Colab, its Drive folder) the current folder.

## 4. Data

- **External datasets** (published by someone else) are never copied into the kit or the notebook.
  Register them in `ai_learning_kit/datasets/__init__.py` with the owner, the owner's download
  address, the checksum of the exact file, its size, the licence note and the citation, and list
  them in the session's `DATASETS`. `kit.start` downloads them from the owner the first time, checks
  the checksum and caches them. Helpers open them with `datasets.fetch(name)`.
- **Small research datasets that a library already ships** (Zachary's karate club and Les
  Misérables in networkx, the iris data in scikit-learn) come from that library, through a helper.
- **Synthetic or fictional data** is generated by a helper with a fixed seed, or stored in the
  kit as a packaged file when generating it is not practical.
- **Reference results** (frozen outputs of the run shown on the slides) are packaged with the
  session, in `units/<unit>/<session>/reference/`, and read through `T.ROOT / "reference"`.

## 5. Helpers

- A session's helpers are one module (`TOOLS = ".tools"`), returned by `kit.tools()`. Every
  `T.<name>` a notebook uses must exist there. **(checked)**
- Helpers never change once a version is released, so a notebook pinned to that version keeps
  giving the numbers on its slides. A change is a new function, or a new session version.

## 6. Metadata

`metadata["ai_learning_kit"]` holds **(checked)**:

| Key | Meaning |
|---|---|
| `unit`, `session` | the session in the kit, e.g. `"ICS5111"`, `"S02"` |
| `title` | the notebook's title as students see it |
| `role` | `prepare`, `explore`, `practice` or `session` |
| `kit_version`, `install` | written by the release step |
| `tasks` | the task ids the notebook answers (empty when it checks itself) |
| `runs_unfilled` | `false` only when blanks raise errors until filled (older notebooks) |

Notebook Tutor reads this block to recognise the notebook, to fetch the session's scope and helpers
for its explanations, and to warn when the notebook was written for another kit version.

## 7. Saved outputs

Notebooks are committed **executed**, so that a student who cannot run a cell still sees the
expected result. Saved outputs contain no errors, except in cells tagged `raises-exception` (a
cell that demonstrates an error on purpose). **(checked)**

## 8. Releasing

`python -m ai_learning_kit.dev.release X.Y.Z` stamps every notebook, rebuilds
`notebooks/README.md` (the Open-in-Colab links for that version) and runs the validator. After
the pull request is merged, create the tag `vX.Y.Z` on main, then update Notebook Tutor to bundle
the release. Links on the VLE point to `notebooks/README.md` or to a notebook's Colab link.
