# Datasets for Part B (graphs)

Part B uses a fixed set of datasets, and every session from Session 02 onwards draws on the same ones. Each dataset is described below: what it contains, what one row means, where it comes from and how the notebooks read it.

| Dataset | Kind | Files | Used for |
|---|---|---|---|
| SciFact | real, published | `scifact/corpus.jsonl` (and, for retrieval, `scifact/queries.jsonl`, `scifact/qrels/test.tsv`) | text turned into graphs; document graphs; retrieval with graphs; the project |
| StudyHub | fictional, generated | `studyhub/users.csv`, `studyhub/replies.csv` | a directed, weighted interaction graph: paths, reachability, structure, centrality |
| Two small graphs | fictional, written in the notebooks | none: each notebook lists their edges | checking an algorithm or a measure by hand |

The notebooks look for the files in a folder called `data` next to the notebook (for example `data/studyhub/users.csv`). If the StudyHub files are not there, the notebooks download them from this repository. SciFact is the copy you already use for Part A.

## SciFact

**What it is.** SciFact is a collection of 5,183 abstracts of biomedical research papers, together with 1,409 scientific claims written by experts (for example, "Vitamin D supplementation reduces the risk of respiratory infection"). For each claim, the abstracts that support or contradict it are marked. It was built for the task of scientific claim verification: given a claim, find the evidence for or against it.

**What one record means.** Each line of `corpus.jsonl` is one abstract, with its identifier, its title and its text. Part B builds graphs from the abstracts: abstracts and terms as the two sides of a bipartite graph (the inverted index), terms linked when they occur in the same abstract, and abstracts linked to their most similar abstracts (the kNN document graph).

**Versions.** Part A uses the BEIR version (fields `_id`, `title`, `text`). The notebooks also read the original release from the Allen Institute for AI (fields `doc_id`, `title`, `abstract`, the abstract as a list of sentences). The 5,183 abstracts and their identifiers are the same in both.

**Where it comes from.** Wadden, D., Lin, S., Lo, K., Wang, L. L., van Zuylen, M., Cohan, A. and Hajishirzi, H. (2020). Fact or fiction: Verifying scientific claims. In *Proceedings of the 2020 Conference on Empirical Methods in Natural Language Processing (EMNLP)*, pp. 7534–7550. The BEIR version is described in Thakur, N., Reimers, N., Rücklé, A., Srivastava, A. and Gurevych, I. (2021). BEIR: A heterogeneous benchmark for zero-shot evaluation of information retrieval models. In *Proceedings of the NeurIPS Datasets and Benchmarks Track*.

**Licence.** CC BY-NC 2.0: non-commercial use, with attribution.

**How to get it.** Use the copy on the VLE, the same one as in Part A, and put `corpus.jsonl` in `data/scifact/`. The original release is also available from the Allen Institute for AI (github.com/allenai/scifact), and the BEIR version from the BEIR authors.

## StudyHub

**What it is.** StudyHub is a course discussion forum that does not exist. It has 300 registered users: 296 members, three tutors and one announcements account (a bot). The users and their replies were generated by a program with a fixed random seed (2205), so that everyone works with exactly the same data and the same numbers as the session documents. Every name in it is invented; any resemblance to a real person is accidental.

**The files.**

- `users.csv` has one row per registered user, with two columns: `user` (a unique user name, such as `kristina_debono`) and `role` (`member`, `tutor` or `bot`).
- `replies.csv` has one row per pair of users, with three columns: `author`, `replier` and `replies`. A row `author = a, replier = b, replies = 3` means that b replied three times to posts written by a.

**How it becomes a graph.** Each user is a node. Each row of `replies.csv` is a directed edge from `author` to `replier`: what the author posted reached the replier. The column `replies` is the edge weight, an interaction frequency (more replies means a stronger tie, not a longer distance). Two features of the files are deliberate, because real data has them too:

- 13 registered users never posted or replied. They appear in `users.csv` but in no row of `replies.csv`, so a graph built from the replies alone leaves them out.
- 31 rows have the same user as author and replier (people replying in their own threads). These are self-loops: they carry no information from one user to another.

**Numbers to check your copy.** 300 users; 3,968 rows of replies; 4,969 replies in all; 31 self-loops. File checksums (SHA-256): `users.csv` 41d875f38fd1ac3ca582eb4e69c58e369bf9584e16c88e58f93b6cbe9b05fd1c, `replies.csv` 921f5b6da1c001674ec7b23345dc0ef98b8ff0b56f30862136a3121313743ae6.

**Licence.** Fictional data created for the unit; free to use for study.

## The two small graphs

Two graphs are small enough to be checked with pencil and paper. Their edges are listed in the notebooks themselves, so they need no files.

- **Eight students who know each other** (undirected). Amy, Ben, Clara, Dylan, Ella, Fabio, Gianni and Hana; an edge means the two know each other. Every edge carries two numbers: `km`, the distance between their homes, and `msgs`, the number of messages they exchange per week.
- **Eleven forum users** (directed). Amy to Kurt; an edge from u to v means that v replied to u at least once, so what u posted reached v. Kurt registered but never posted or replied.

Both are invented.
